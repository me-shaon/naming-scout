# Build transliteration sweep into variant generation for non-Latin scripts (Bangla, Arabic, etc.). Document that single words from non-English vocabularies are nearly all taken on .com; compounds and ccTLDs have more room. Add local-language example (Bangladeshi ledger product using Bangla commerce vocabulary).

**Question:** Should the skill support non-English names, including transliteration variants?

Bangladeshi founder using 'dokan' or 'halkhata' is in scope; skill should not assume English-only. Live data showed dokan variants (21 generated) are 80% registered, but Halkhata compounds (amarhalkhata, halkhataapp) had 50%+ availability. ccTLDs (.bd, .com.bd) lack RDAP verification, limiting utility.

**Decided by:** proposed by human human:shaon.cse81@gmail.com, accepted by agent agent:claude-code

## Not taken

- **Out of scope; support English only** (rejected): Skill claims to work for founders globally. Defaulting to English excludes real users and their naming practices.
- **Warn users not to use non-English words** (rejected): Live data disproves the warning. Bangla compounds and .app domains had genuine availability. Generic warning is patronizing and wrong.
