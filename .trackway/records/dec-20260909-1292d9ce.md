# Add searchability grades (ownable/contested/crowded) as a separate axis from domain state, grounded in page-one search results for the name alone.

**Question:** Should the skill evaluate SEO ranking prospects for domain names?

Founders care about ranking for their own name. Exact-match myth (stopped being true in 2012) misleads. Grades predict time-to-first-page and content strategy cost better than domain availability alone. One example (freelancer budgeting app) showed Granary moved from top pick to contested grade due to competing historical usage.

**Decided by:** proposed by human human:shaon.cse81@gmail.com, accepted by agent agent:claude-code

## Not taken

- **Skip SEO entirely** (rejected): Founders raise it; silence suggests it is not considered. Collision detection alone misses the ranking difficulty.
- **Generate a numeric ranking score** (rejected): Searchability is judgment from page-one inspection, not a measured difficulty metric. Examples must disclose this; scoring falsely implies precision.
